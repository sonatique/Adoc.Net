## 1. AdocEngine Convert() — Caching Logic

**File**: `src/AdocNet.Core/AdocEngine.cs`

### Convert() Flow (lines 229-268)

```
1. If caching disabled → ConvertUncached (parse → extensions → render → output processors)
2. If caching enabled:
   a. Compute inputHash = SHA-256(input)
   b. Compute renderKey = SHA-256(inputHash | format | optionsHash)
   c. Check render cache → if hit, run output processors, write, return
   d. Check parse cache → if hit, use cached doc; else parse and cache
   e. Run extensions on doc (mutates AST)
   f. Render to buffer
   g. Cache rendered bytes in render cache (key = renderKey)
   h. Run output processors
   i. Write to output
```

### Render Cache with Extensions — CRITICAL FINDING

**The beta.12 rules state**: "Render cache currently DISABLED when extensions are registered (safety decision in beta.10)."

**Actual code**: The render cache is used **regardless** of whether extensions are registered.
There is NO condition checking `_documentProcessors.Count > 0` or similar before using
the render cache. The render cache key is `inputHash + format + options` — it does NOT
include extension identity or state.

**Consequence**: If extensions are non-deterministic (e.g., inject timestamps, random IDs),
the render cache would serve stale/incorrect results. For deterministic extensions, the
cache is correct because same input always produces the same AST mutations.

**Beta.12 action needed**: Add a guard in `Convert()` that only uses the render cache
when ALL registered processors declare `IsDeterministic = true` via `IExtensionCapabilities`.
If any processor doesn't implement the interface or returns false, skip the render cache
(fall through to parse cache + extensions + render).

### Extension Registration (lines 114-161)

- `RegisterDocumentProcessor()`, `RegisterBlockProcessor()`, `RegisterInlineProcessor()`,
  `RegisterOutputProcessor()` — all fluent, FIFO order.
- Registration frozen after first `Convert()` call (`_frozen` flag, line 527-532).
- `RegisterExtensions(List<object>)` (line 500-526) dispatches to typed lists +
  handles `IExtensionLifecycle.Initialize()`.

### Other Caching API

- `EnableCaching` property (default false, opt-in). Setting false clears caches (line 64-78).
- `MaxCacheEntries` property (default 16, min 1). Adjusts LRU capacity live (line 84-95).
- `ClearCache()` — public method to clear both caches (line 413-417).
- `ParseIncremental(DocumentSnapshot)` — cache-assisted re-parse for editor scenarios (line 388-407).

## 2. LruCache API

**File**: `src/AdocNet.Core/Caching/LruCache.cs`
**Visibility**: `internal sealed class`

### Constructor
- `LruCache(int capacity)` — capacity >= 1 required.

### Properties
- `int Count` — current entries, thread-safe read via lock.
- `int Capacity` — get/set, evicts excess on reduction.

### Methods
- `bool TryGet(TKey key, out TValue value)` — O(1) lookup, promotes to MRU on hit.
- `void Set(TKey key, TValue value)` — O(1) add/update, evicts LRU if over capacity.
- `void Clear()` — removes all entries.

### Thread Safety
All operations synchronized via `lock (_lock)`. Dictionary + doubly-linked list for O(1) ops.

### Internal Structure
- `Dictionary<TKey, LinkedListNode<CacheEntry>> _map` — key lookup
- `LinkedList<CacheEntry> _list` — LRU ordering (front = MRU, back = LRU)
- `CacheEntry` — readonly struct with Key + Value fields.

## 3. CacheKeyBuilder

**File**: `src/AdocNet.Core/Caching/CacheKeyBuilder.cs`
**Visibility**: `internal static class`

### Methods

- `ComputeInputHash(string input)` — SHA-256 hex of UTF-8 bytes. Used as parse cache key.
- `ComputeRenderKey(string inputHash, string format, RenderOptions options)` —
  Composite key: `SHA-256("{inputHash}|{format}|{optionsHash}")`.
  Options hash computed via reflection over all public instance properties, sorted by name,
  using InvariantCulture formatting.

### SHA-256 Implementation
- `net5.0+`: `SHA256.HashData()` + `Convert.ToHexString()`
- `netstandard2.0`: `SHA256.Create()` + `BitConverter.ToString().Replace("-", "")`

### Key for Beta.12
The `ComputeRenderKey` method does NOT include extension identity in the key.
For persistent cache, the key must also include the AdocNet version (for invalidation).

## 5. ProcessingPipeline — Execution Order

**File**: `src/AdocNet.Core/Extensions/ProcessingPipeline.cs`
**Visibility**: `internal static class`

### Execution Order (guaranteed, FIFO)
1. **Document processors** — each receives the full `DocumentNode`, in registration order
2. **Block processors** — depth-first walk, all processors checked per block (FIFO)
3. **Inline processors** — depth-first walk through block containers, FIFO per inline

### No Priority Concept
Processors execute strictly in registration order (FIFO). There is no priority field,
no sorting, no reordering. Beta.12 adds `IExtensionPriority` with `int Priority`
(lower = first, default 1000) and sorts processors within each type by priority,
preserving FIFO within same priority.

### Failure Tracking
- `TrackFailure()` increments per-processor counter in `failureCounts` dictionary.
- Counter resets on success (`failureCounts.Remove(processor)` after successful run).
- At `maxFailures` consecutive failures, processor added to `disabledProcessors` set.
- Disabled processors are skipped in all subsequent invocations.

### AST Mutation
- `NodeReplacements` used for block/inline replacement during walk.
- Replacements applied after each processor batch, with index re-check.

## 6. ExtensionDirectoryLoader — Version Compatibility

**File**: `src/AdocNet.Core/Extensions/ExtensionDirectoryLoader.cs`

### IsVersionCompatible(string current, string minimum)
- Parses semver: splits on `-` to get numeric part and prerelease suffix.
- Compares numeric parts via `System.Version.CompareTo()`.
- Same numeric version: release > prerelease, prerelease compared ordinally.
- Returns true if current >= minimum.

### IsApiVersionCompatible(string host, string? extension)
- Compatible when: extension major == host major AND extension minor <= host minor.
- Null extension API version always compatible (pre-beta.9 extensions).

### LoadInstalledExtensions Flow
1. Scan subdirectories of extensions root (alphabetical order).
2. Load `extension.json` manifest for each.
3. Check enabled state via registry (`registry.Find(name)` → skip if `!Enabled`).
4. Check `minAdocNetVersion` compatibility → skip with warning if incompatible.
5. Check entry DLL exists → skip with warning if missing.
6. Load assembly via `ExtensionLoader.LoadAssembly()`.

### NOT present (beta.12 will add)
- **maxAdocNetVersion** check — only `minAdocNetVersion` is checked.

## 8. Key Architecture Points for Beta.12

### Render Cache Key Does Not Include Extension State
The render cache key is `SHA-256(inputHash + format + optionsHash)`. It does not include:
- Which extensions are registered
- Whether extensions modified the AST
- Extension versions or configuration

This is safe ONLY if extensions are deterministic. Beta.12 must guard on this.

### LruCache Is Internal
`LruCache<TKey, TValue>` is `internal sealed` — cannot be used from external assemblies.
Persistent cache will wrap or complement it, not replace it.

### Parse Cache Stores Object References
Parse cache stores `DocumentNode` (in-memory object graph). Not serializable without
AST modification. Persistent cache applies to **render cache only** (byte[] is trivial).

### SimpleJsonParser Supports Flat Objects + String Arrays
For `maxAdocNetVersion`, just add it as another flat field in `ParseFlatObject()` —
no JSON parser changes needed. The manifest already handles optional string fields.

### Extension Registration Is FIFO + Frozen
After first `Convert()`, no new processors can be registered. Beta.12's priority
sorting must happen at freeze time or during `Convert()`, not at registration time.
