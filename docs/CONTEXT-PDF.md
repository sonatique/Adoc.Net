## 3. Font System

### 3.1 Standard Fonts (Helvetica / Courier)

The PDF 1.4 spec defines 14 standard fonts that all conformant viewers must support. PdfWriter uses four:

| Key | PDF Font | Usage |
|-----|----------|-------|
| F1 | Helvetica | Body text |
| F2 | Helvetica-Bold | Bold text, headings |
| F3 | Helvetica-Oblique | Italic text |
| F4 | Courier | Monospace / code |

**Metrics**: Hardcoded per-character width tables in `PdfWriter`:
- `HelveticaWidths` — dictionary of `char → float` for ASCII printable characters (95 entries)
- `HelveticaBoldWidths` — same for bold variant
- `HelveticaDefaultWidth` = 0.556f (fallback for unmapped chars)
- `HelveticaBoldDefaultWidth` = 0.611f
- `CourierAvgWidth` = 0.6f (monospace — all chars same width)

Widths are in units where 1.0 = 1000 font units. Multiply by fontSize to get points.

**Encoding**: WinAnsiEncoding (Latin-1 subset). Non-Latin characters render as `?` or are escaped with `\xxx` octal codes for the 128-255 range.

### 3.2 TrueType Font Embedding

When `PdfRenderOptions.FontPath` (and/or Bold/Italic/Mono variants) is set:

1. `TrueTypeFont.Parse()` reads the `.ttf` file — extracts cmap, hmtx, head, OS/2, name tables
2. `PdfWriter.RegisterEmbeddedFont()` allocates a placeholder PDF object and maps the standard key (F1-F4) to an embedded key (F5+)
3. During text output, `WriteText()` checks `IsEmbeddedFont()` — if true, text is encoded as hex glyph IDs (`<0041 0042>`) instead of `(AB)`
4. In `ToBytes()`, font objects are finalized: CIDFont Type2, /ToUnicode CMap, /FontDescriptor with embedded font stream

**Limitations**:
- Only `.ttf` files (not `.ttc` TrueType Collections)
- Only cmap format 4 (BMP Unicode) — no format 12 (full Unicode > U+FFFF)
- No font subsetting (entire font file is embedded)
- No bold/italic synthesis — separate font files required

### 3.3 Text Measurement

`PdfWriter.MeasureText(text, fontKey, fontSize)`:
- For standard fonts: looks up each char in the width table, sums widths × fontSize
- For embedded fonts: calls `TrueTypeFont.MeasureText()` which uses cmap + hmtx
- Unknown characters fall back to `HelveticaDefaultWidth`

## 4. Layout System

### 4.1 Page & Cursor Model

- Coordinate system: origin at bottom-left, Y increases upward (PDF convention)
- `_cursorY` starts at `pageHeight - marginTop`, decreases as content is written
- `EnsurePage()` checks if cursor is below bottom margin; if so, finishes current page and starts a new one
- `MoveCursor(dy)` decreases `_cursorY` by `dy`

### 4.2 Text Wrapping

`WrapText(text, font, fontSize, maxWidth)` → `List<string>`:
- Splits on spaces, accumulates words into lines
- When a word would exceed `maxWidth`, starts a new line
- Handles words longer than `maxWidth` by breaking mid-word

`WrapSegments(segments, maxWidth)` → `List<List<TextSegment>>`:
- Same algorithm but preserves font/style across segments
- Returns a list of lines, each a list of `TextSegment`s

`WriteWrappedSegments(segments, leading, justify)`:
- Wraps segments, then renders each line
- If `justify=true`, non-last lines get extra word spacing to fill width

### 4.3 Block Positioning

All blocks follow a simple vertical flow:
1. `EnsurePage()` — start new page if needed
2. Write content (text, drawing commands)
3. `MoveCursor(spacing)` — add vertical spacing

No floats, no columns, no absolute positioning.

### 4.4 Table Layout

Two sizing strategies:
1. **Explicit column specs** — when `table.Columns` has varying weights, distribute proportionally
2. **Auto-sizing** — measure min widths (longest word) and text volume per column, then distribute remaining space proportionally

Row rendering: two-pass per row:
1. Wrap text in each cell, determine max line count → row height
2. Render each cell at the correct x position with alignment

### 4.5 Code Blocks

- Gray background rectangle drawn first (estimated from line count × leading)
- Language label in italic 8pt if present
- Each line rendered with `WriteWrappedVerbatimText` (wraps long lines)
- Callout list rendered after the block

### 4.6 Admonitions

- Type label in bold (e.g., "NOTE:")
- Block admonitions: recursively render children
- Inline admonitions: render inline segments

### 4.7 Structural Blocks (Example, Quote, Sidebar)

- Left border line drawn from start to end Y
- Children rendered recursively with increased indent level

## 6. Image Handling

### 6.1 Image Loading

`PdfRenderer.TryLoadImage(target, out ImageInfo)`:
- Resolves path relative to `PdfRenderOptions.BaseDirectory`
- Returns false if BaseDirectory is null or file doesn't exist
- Tries JPEG first, then PNG

### 6.2 JPEG Embedding

- Entire JPEG data passed through as-is (DCTDecode filter)
- Dimensions and components extracted from SOF0/SOF2 markers
- Color space: DeviceRGB (3 components) or DeviceGray (1 component)

### 6.3 PNG Embedding

- IDAT chunks collected and decompressed (zlib/deflate)
- Scanlines de-filtered (None, Sub, Up, Average, Paeth)
- RGBA split into RGB data + alpha SMask
- Re-compressed with DeflateStream for FlateDecode
- Supports: 8-bit RGB, RGBA, Grayscale. Non-interlaced only.

### 6.4 Rendering

- Scaled to fit content width, maintaining aspect ratio
- Page break if needed
- Fallback: gray placeholder rectangle with `[Image: alt]` text

## 7. Hyperlinks

- `PdfWriter.AddLinkAnnotation(x, y, width, height, uri)` — records annotation for current page
- Link annotations rendered as `/Type /Annot /Subtype /Link` with `/A /S /URI` action
- Created in `AppendInlineSegments` when `TextSegment.Url` is set
- Currently link text has no visual styling (no underline, no color)

## 8. Headers & Footers

- `PdfWriter.HeaderTemplate` / `FooterTemplate` — string with `{page}` placeholder
- `ShowPageNumbers` — shorthand that sets footer to `"Page {page}"`
- Rendered in `AppendHeaderFooter()` just before `FinishPage()`
- Header: centered in top margin area, 9pt Helvetica
- Footer: centered in bottom margin area, 9pt Helvetica
- Page number formatted with `CultureInfo.InvariantCulture`

## 10. Observations for Beta.3

1. **PdfWriter is 1071 lines** — well over the 500-line warning threshold. It combines PDF object management, text measurement, text rendering, drawing, image embedding, and serialization. Consider splitting if adding significant new features.

2. **Font metrics are ASCII-only for standard fonts** — the `HelveticaWidths` table covers U+0020–U+007E only. Characters outside this range (including Latin-1 U+00A0–U+00FF) use the default width, causing inaccurate measurement.

3. **No font subsetting** — embedded TrueType fonts include the entire font file. For typical documents this adds 50-500KB per font face.

4. **No cmap format 12** — only format 4 (BMP) is parsed. Characters above U+FFFF (emoji, etc.) won't get correct glyph IDs.

5. **Link annotations have no visual styling** — hyperlink text looks identical to regular text in PDF output (no blue color, no underline).

6. **Table layout doesn't handle row/col spans** — `RenderTableRow` treats each cell as colspan=1 for positioning purposes. The column count is taken from the first row's child count, ignoring spans.

7. **No TOC in PDF** — `TocNode` is not handled in `RenderBlock`.

8. **Structural block border goes wrong across pages** — the left border line is drawn from `startY` to `endY`, but if children span multiple pages, `endY` is on a different page than `startY`.

9. **Code block background rectangle is approximate** — height is estimated from line count before rendering, which may not match actual wrapped output.

10. **WinAnsiEncoding for standard fonts** — non-Latin characters outside the 128-255 range cannot be rendered. Only TrueType embedding enables full Unicode.
