## 2. AST Base Class Hierarchy

```
AstNode                          (abstract — namespace AdocNet.Ast)
├── Source: SourceRange
├── Children: IReadOnlyList<AstNode>
├── Kind: AstNodeKind             (abstract)
├── AddChild(AstNode)
├── InsertChild(int, AstNode)
├── GetProperties(): IEnumerable<KVP<string,string>>
│
├── BlockNode                    (abstract — extends AstNode)
│   ├── Id: string?
│   ├── Reftext: string?
│   ├── Roles: IReadOnlyList<string>
│   └── Substitutions: SubstitutionKind?
│
├── InlineNode                   (abstract — extends AstNode)
│   (no additional properties)
│
└── DocumentNode                 (sealed — extends AstNode directly, NOT BlockNode)
    ├── Title: string?
    ├── Attributes: IReadOnlyDictionary<string,string>
    ├── SetAttribute(name, value)
    └── RemoveAttribute(name)
```

**Important**: `DocumentNode` extends `AstNode` directly, NOT `BlockNode`.

`TableRowNode` and `TableCellNode` also extend `AstNode` directly, NOT `BlockNode`.

## 4. Existing Renderer Pattern

### 4.1 Interface

```csharp
// AdocNet.Core — namespace AdocNet
public interface IDocumentRenderer
{
    string Format { get; }
    void Render(DocumentNode document, Stream output, RenderOptions options);
}
```

### 4.2 Base Class — `DocumentRendererBase`

The base class provides **type-switch dispatch** (NOT a visitor pattern):

```csharp
// Dispatches blocks:
protected void RenderBlock(BlockNode node, RenderContext context)
{
    switch (node)
    {
        case SectionNode n:          RenderSection(n, context); break;
        case ParagraphNode n:        RenderParagraph(n, context); break;
        case ListNode n:             RenderList(n, context); break;
        // ... one case per block type
        default: throw new NotSupportedException(...);
    }
}

// Dispatches inlines:
protected void RenderInline(InlineNode node, RenderContext context)
{
    switch (node)
    {
        case TextInlineNode n:       RenderTextInline(n, context); break;
        case StrongInlineNode n:     RenderStrongInline(n, context); break;
        // ... one case per inline type
        default: throw new NotSupportedException(...);
    }
}
```

Each concrete renderer (e.g., `HtmlRenderer`) overrides virtual methods:

```csharp
protected override void RenderSection(SectionNode node, RenderContext context) { ... }
protected override void RenderParagraph(ParagraphNode node, RenderContext context) { ... }
// etc.
```

### 4.3 RenderContext

```csharp
public sealed class RenderContext
{
    public DocumentNode Document { get; }
    public RenderOptions Options { get; }
    public IReadOnlyDictionary<string, string> Attributes { get; }
    public T GetOrCreate<T>(Func<T> factory) where T : class;  // per-render state
}
```

### 4.4 Pattern Summary

1. Entry: `Render(DocumentNode, Stream, RenderOptions)` → creates `RenderContext` → calls abstract `RenderDocument`
2. `RenderDocument` iterates `document.Children`, calling `RenderBlock` for each
3. `RenderBlock` type-switches to the correct `Render*` virtual method
4. Each `Render*` method processes the node's properties, then recursively calls `RenderInlines` / `RenderBlocks` for children
5. `RenderInlines` / `RenderBlocks` are convenience loops calling `RenderInline` / `RenderBlock` per item

**Key insight for Layout builder**: The Layout builder should follow the same dispatch pattern — a central switch that converts each AST node type to its corresponding Layout node type. The builder does NOT need to inherit from `DocumentRendererBase` because it produces a layout tree, not a stream output.

## 6. Observations for Layout + Avalonia Work

1. **`DocumentNode` is NOT a `BlockNode`** — the Layout builder must handle it as a special root case, not through `RenderBlock`.

2. **`TableRowNode` and `TableCellNode` extend `AstNode` directly** — they are neither `BlockNode` nor `InlineNode`. The Layout builder needs explicit handling for these.

3. **Inline nodes with children shadow `AstNode.Children`** — `StrongInlineNode.Children`, `EmphasisInlineNode.Children`, `MonospaceInlineNode.Children`, and `HighlightInlineNode.Children` are typed `IReadOnlyList<InlineNode>` using `new`. The Layout builder MUST use these typed properties.

4. **Dual Text/Inlines representation** — `ParagraphNode`, `ListItemNode`, `AdmonitionNode`, `TableCellNode`, `FootnoteInlineNode`, `BibliographyEntryNode`, and `DescriptionItemNode` all carry both raw `Text` and parsed `Inlines`. The Layout builder should prefer `Inlines` when non-empty.

5. **`DelimitedBlockNode` has two modes** — verbatim blocks (Literal, Listing, Source) use `Content` string; structural blocks (Example, Quote, Sidebar, Open, Verse) use `Children`. The Layout builder must check `BlockKind` to decide which to use.

6. **No polymorphic rendering** — the existing renderer uses type-switch dispatch, not virtual dispatch on nodes. The Layout builder should follow the same pattern.

7. **All AST types are sealed** — no subclassing AST nodes. Layout types should also be sealed.

8. **Namespace conventions** — AST is `AdocNet.Ast`, Core types are `AdocNet`. Layout should be `AdocNet.Layout` with sub-namespaces like `AdocNet.Layout.Builders`.
