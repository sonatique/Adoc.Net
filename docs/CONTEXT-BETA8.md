## 2. ExtensionDirectoryLoader (`src/AdocNet.Core/Extensions/ExtensionDirectoryLoader.cs`)

### Public Methods

- **`static GetDefaultExtensionDirectory() -> string`**
  Returns `~/.adocnet/extensions/` using `Environment.SpecialFolder.UserProfile`.

- **`static LoadInstalledExtensions(string? extensionsRootDir, Action<string>? onWarning) -> List<object>`**
  Scans subdirectories alphabetically. For each: loads manifest, checks version compatibility,
  loads entry DLL via `ExtensionLoader.LoadAssembly()`. Returns combined list of instantiated processors.

### Internal Methods

- **`static GetCurrentAdocNetVersion() -> string`**
  Reads `AssemblyInformationalVersionAttribute`, strips SourceLink hash suffix.

- **`static IsVersionCompatible(string current, string minimum) -> bool`**
  Semver comparison: numeric parts first, then prerelease (release > any prerelease of same version).
  Unparseable minimum -> allow. Unparseable current -> reject.

### Key Facts

- Subdirectories sorted alphabetically by `Path.GetFileName()` for deterministic order
- Delegates to `ExtensionLoader.LoadAssembly()` for actual DLL loading
- Skips extensions with incompatible versions (warns, doesn't crash)
- Skips extensions with missing entry DLL (warns, doesn't crash)

## 3. SimpleJsonParser (`src/AdocNet.Core/Extensions/SimpleJsonParser.cs`)

### Public API

- **`static ParseFlatObject(string json) -> Dictionary<string, string>`**
  Parses `{ "key": "value", ... }`. Non-string values are silently skipped.
  Throws `FormatException` on malformed JSON. Returns empty dict for empty object.

### Capabilities

- Parses flat JSON objects with string-only values
- Handles JSON string escaping (backslash escapes, `\uXXXX`)
- Skips non-string values (numbers, booleans, null) without error
- Skips nested objects and arrays without error (balanced brace/bracket tracking)
- Case-sensitive keys (ordinal comparison)

### Limitations — CRITICAL FOR BETA.8

- **No array parsing**: Cannot parse `[...]` as a top-level or nested structure
- **No nested object parsing**: Can skip them but cannot extract their contents
- **No number/boolean extraction**: Only string values are returned
- **Flat objects only**: `{ "key": "value" }` — nothing deeper

### Internal Details

- `ReadString(json, ref i)` — reads a quoted JSON string with escape handling
- `Unescape(raw)` — handles `\"`, `\\`, `\/`, `\n`, `\r`, `\t`, `\b`, `\f`, `\uXXXX`
- `SkipValue(json, i)` — skips any JSON value (string, number, boolean, null, object, array)
- `SkipWhitespace(json, i)` — whitespace handling
- 209 lines total, well-structured and tested

## 7. JSON Gap Analysis — What registry.json Needs vs SimpleJsonParser

### Registry Format (from beta8 rules)

```json
{
  "version": 1,
  "extensions": [
    {
      "name": "diagram",
      "version": "1.0.0",
      "description": "Diagram support",
      "path": "/abs/path/diagram"
    }
  ]
}
```

### What SimpleJsonParser CAN Do

- Parse flat `{ "key": "value" }` objects (string values only)
- Skip non-string values (numbers, arrays, objects)

### What SimpleJsonParser CANNOT Do

| Requirement | Supported? | Details |
|-------------|-----------|---------|
| Top-level `"version": 1` (integer value) | NO | Skips non-string values |
| Top-level `"extensions": [...]` (array) | NO | Skips arrays entirely |
| Parsing array elements | NO | No array support at all |
| Parsing nested objects within arrays | NO | Can skip but not extract |

### Gap Summary

The registry format needs:
1. **Integer value extraction** — `"version": 1` (could work around by using `"version": "1"`)
2. **Array-of-objects parsing** — `"extensions": [{ ... }, { ... }]` (no workaround)
3. **Writing/serializing** JSON (SimpleJsonParser is read-only)

### Options for Extending JSON Handling

**Option 1: Extend SimpleJsonParser (Recommended)**
- Add `ParseRegistry()` or `ParseArrayOfFlatObjects()` method
- Scope: parse `{ "version": "1", "extensions": [ {flat}, {flat}, ... ] }`
- ~50-80 lines of new code. Reuse existing `ReadString`, `SkipWhitespace`
- Add `Serialize()` methods for writing registry JSON (string concatenation)
- Keep it internal — no public API surface change
- Pros: zero new deps, bounded scope, reuses existing code
- Cons: hand-written serializer is fragile

**Option 2: Hand-written registry serialization**
- Separate `RegistrySerializer` class for read/write
- Use SimpleJsonParser for the flat object parts, custom code for array structure
- Pros: clean separation
- Cons: duplicates some parsing logic

**Option 3: Add System.Text.Json NuGet package**
- Conditional reference for netstandard2.0 only (net10.0 has it built-in)
- Pros: robust, well-tested, handles all JSON
- Cons: breaks Core's zero-external-dep philosophy

**Recommendation**: Option 1. Extend `SimpleJsonParser` with minimal additions for the
specific registry format. Keep it internal. The registry JSON is simple and well-defined —
we don't need a general-purpose JSON library.
