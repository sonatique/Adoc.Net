```csharp
public sealed class AdocEngine

```

### Current Flow (beta.4)

```
Convert(input, output, options):
  1. doc = Parser(input)           // parse AsciiDoc → DocumentNode
  2. Renderer.Render(doc, output, options)  // render to stream
```

**No extension points.** Beta.5 adds processor registration and pipeline execution
between steps 1 and 2.

## 4. RenderContext (`src/AdocNet.Core/RenderContext.cs`)

```csharp
public sealed class RenderContext
{
    // Constructor
    public RenderContext(DocumentNode document, RenderOptions options);

    // Properties
    public DocumentNode Document { get; }
    public RenderOptions Options { get; }
    public IReadOnlyDictionary<string, string> Attributes { get; }  // => Document.Attributes

    // Per-render state
    public T GetOrCreate<T>(Func<T> factory) where T : class;
}
```

**State model**: `_state` is a `Dictionary<Type, object>`. Keyed by `typeof(T)`,
so each state type gets one instance per render. Extensions use this for per-render state.

## 6. AST Node Types (relevant to extensions)

### AstNode (`src/AdocNet.Ast/AstNode.cs`)

```csharp
public abstract class AstNode
{
    public SourceRange Source { get; set; }
    public IReadOnlyList<AstNode> Children { get; }  // backed by List<AstNode>
    public abstract AstNodeKind Kind { get; }
    public void AddChild(AstNode child);
    public void InsertChild(int index, AstNode child);
    public virtual IEnumerable<KeyValuePair<string, string>> GetProperties();
}
```

**Important**: No `RemoveChild` or `ReplaceChild` methods exist. The backing `_children`
is `List<AstNode>` but only exposed as `IReadOnlyList<AstNode>`. Beta.5 extension
mutation (e.g., replacing a diagram code block with an image block) will need either:
- New mutation methods on `AstNode` (but rules say "do not modify AST")
- The pipeline to handle node replacement at the tree-walk level

| Flag | Description |
|------|-------------|

### Extension Relevance

Beta.5 does NOT add CLI flags (static registration only, via code API).
The CLI creates an `AdocEngine` internally — extensions would need to be registered
in custom code, not via CLI.

## 10. AST Mutation Consideration

The beta.5 rules specify that extensions MAY:
- Add children to a node (`AddChild` exists)
- Remove children from a node (NO method exists)
- Replace a node with a different node (NO method exists)
- Modify node properties (setters exist on some properties)

Current `AstNode` mutation methods:
- `AddChild(AstNode)` — exists
- `InsertChild(int, AstNode)` — exists
- Remove / Replace — **not available**

The pipeline implementation will need to handle node replacement at the tree-walk level
(e.g., the pipeline walker replaces nodes in the parent's children list) rather than
requiring extensions to call mutation methods on `AstNode` directly.
