# AdocNet v1.0.0 Readiness Assessment

**Date**: 2026-04-21 (post-v1.0.0-beta.26)
**Status**: Technically very close, practically a few non-code steps away.

This document captures the honest current-state assessment and a concrete
roadmap to the first non-beta release. Author it once, revisit before each
RC tag.

## Executive summary

The codebase is essentially v1.0.0-quality already. What's missing is not
code — it's external validation, broader compatibility testing on real
corpora, and the commitment to API stability that the version number itself
implies.

Estimated total effort: **~3 days of code + a calendar window for feedback**.

## What's strong (no blockers here)

| Area | Status |
|---|---|
| Test coverage | 2907 tests, 0 regressions, growing every release |
| Format coverage | HTML, PDF, EPUB, DocBook, Reveal.js, Man — all 6 formats covered with structural diff tooling and Tier 1+2 parity fixes applied |
| Architecture | Extensions, caching, hot-reload, LSP server, Avalonia preview, CLI tools, themes — most of what Asciidoctor offers |
| Code quality | Deterministic output, comprehensive XML docs, no dead code, performance benchmarks |
| Cross-platform | CI green on Windows / Linux / macOS |
| Determinism | Output is byte-identical across runs and platforms (PDF since beta.25, HTML/EPUB/DocBook since beta.26) |

## What blocks v1.0.0

### 1. Compatibility tested against ONE document — PARTIALLY DONE

Started post-beta.26 with `tools/parity-sweep.py` running all diff
tools across `spec/conformance/asciidoctor-*.adoc` (5 representative
asciidoctor-style documents covering admonitions, document header,
lists, macros, tables).

**Initial sweep surfaced these gaps** (all fixed):

| Gap | Format | Where |
|---|---|---|
| Missing `<div id="preamble">` wrapper | HTML | content before first section |
| Footer "Last updated" missing timestamp | HTML | localdatetime fallback |
| Missing `docdatetime`/`doctime` parser defaults | HTML | parser |
| Sidebar block `id` attribute | HTML, DocBook | `<div class="sidebarblock">`, `<sidebar>` |
| Timezone `+01:00` vs `+0100` | HTML | parser |
| Inter-doc xref: `<olink>` → `<link xlink:href>` | DocBook | `xref:foo.adoc` |
| `.adoc` extension → `.xml` in xref label | DocBook | label fallback |
| `<formalpara>` xml:id not propagated | DocBook | titled verbatim blocks |
| `<screen>`/`<programlisting>` `linenumbering` attr | DocBook | callout + language paths |
| Admonition `<para>` → `<simpara>` | DocBook | inline-only content rule |

**Final state across the 5-doc corpus**:

| format | min | median | max | sum |
|---|---|---|---|---|
| html | 0 | 0 | 11 | 11 |
| docbook | 0 | 36 | 161 | 253 |
| revealjs | 233 | 370 | 631 | 1949 |
| epub-struct | 1 | 1 | 1 | 5 |

**Remaining work to fully close gap 1**:

a. **HTML**: 1 doc has 11 line residual = smart-quote substitution
   (asciidoctor "replacements" pass: `'` → `'`, `(C)` → `©`, etc.).
   Known feature, separate fix. ~1-2 hours.

b. **DocBook**: tables document has 161 residual lines — table-specific
   structural gaps not yet investigated. Other docs 17-39 lines mostly
   from `<phrase role="term">` wrapping inside emphasis (the `[term]#x#`
   syntax) that we don't emit. ~half day.

c. **Reveal.js**: 233-631 lines per doc — substantial structural gaps:
   asciidoctor-revealjs uses table-based admonition layout, puts
   preamble inside title slide, and many block wrappers differ. This
   is the only format where a real refactor is needed. ~1 day.

d. **EPUB structural**: 1 common-part differing per doc — likely a
   consistent metadata property mismatch (probably package.opf or
   nav.xhtml ordering). Quick triage needed. ~1-2 hours.

e. **Real-world projects** — still untested:
   - Asciidoctor user manual
   - Spring Boot reference docs
   - At least one book-doctype document

   **Effort for remaining**: ~2-3 days.

### 2. No external users yet

Per the historical context: no users, no forks, no watchers. v1.0.0
implies API stability promises — hard to make that promise without
2-3 outside users hitting the API and finding the rough edges.

**Approach**: tag `v1.0.0-rc.1` with the API frozen, actively solicit
real-world testing for 2-3 weeks. This is calendar time, not work time.

### 3. API surface not formally locked

Every beta has been making additive changes. v1.0.0 should declare:
"this is the supported API; changes here are SemVer breaking."

**Concrete deliverable**: audit public types in
- `AdocNet.Core` (AdocEngine, RenderOptions, IDocumentRenderer)
- `AdocNet.Parser` (AdocParser, ParseOptions, ParseResult)
- `AdocNet.Ast` (DocumentNode, all node types)
- Each renderer's options class (HtmlRenderOptions, PdfRenderOptions,
  EpubRenderOptions, DocBookRenderOptions, RevealjsRenderOptions,
  ManRenderOptions)
- Extension interfaces (IDocumentProcessor, IBlockProcessor,
  IInlineProcessor, IOutputProcessor, IExtensionLifecycle, etc.)

Mark each member as **stable** or apply `[Experimental]` if not yet
ready to commit. Anything experimental needs to either get promoted
or removed before v1.0.0.

**Effort**: half day.

### 4. Migration documentation

A "Moving from Asciidoctor to AdocNet" guide. One page with:

- CLI flag mapping table (asciidoctor flag → adocnet flag)
- Attribute support matrix (what works, what's planned, what's not)
- Output format compatibility notes (e.g. "DocBook output is
  byte-identical to asciidoctor for HOWTO.adoc with file mtime
  injection enabled")
- Known issues / intentional differences (e.g. EPUB doesn't bundle
  fonts by default; default theme differs from Asciidoctor's iconic
  red-on-cream — use `--theme asciidoctor` for that)
- Extension migration: AdocNet extensions are .NET assemblies, not
  Ruby gems. Asciidoctor extensions are NOT supported.

**Effort**: half day.

## What does NOT block v1.0.0

These are documented Tier 3 deferrals from the beta.26 sweep — real
or perceived gaps that we've decided are acceptable:

| Item | Reason |
|---|---|
| Man Tier 3 (`.sp` / `.RS` / `.RE` reformat) | AdocNet's `.PP` / `.IP` / `.TP` style produces functionally equivalent output via groff. AdocNet's dialect is actually more portable to mandoc on BSD. |
| EPUB font bundling | Adds ~640 KB per EPUB; opt-in trade-off documented. Default web-safe stack is sufficient for most readers. |
| DocBook `<date>` mtime fallback | Already done (beta.26). Honors `:reproducible:` opt-out. |
| Asciidoctor theme sub-pixel drift | Closed in beta.26 via DevTools-protocol diff. Three remaining cosmetic deltas (pre color, font-family, text-rendering) don't affect layout. |
| Per-format Tier 3 wrappers | Documented in respective `docs/*-PARITY-FIRSTPASS.md` files. None are correctness issues. |

## Possible quick wins worth considering before v1.0.0

These are nice-to-haves that came up during the beta.26 sweep but
weren't in scope:

- **Update README hero section** to mention the parity claim with
  concrete numbers ("byte-identical structural output to Asciidoctor
  for HTML, DocBook, Reveal.js; 33% pixel-diff for EPUB visual layout").
- **Showcase the `--theme asciidoctor` option** more prominently —
  it's the single biggest "I don't have to migrate my existing CSS"
  argument for adoption.
- **Asciidoctor compatibility test gate in CI** — currently the diff
  tools are dev-only. Adding a job that runs `html-diff.py` etc.
  against a small corpus and fails the PR if regression appears
  would prevent silent parity drift.
- **Performance comparison table** in README — AdocNet vs
  asciidoctor (Ruby) on the same corpus. We already have benchmarks;
  surfacing them publicly is a low-effort marketing win.
