== Getting Started

{product-name} is a bidirectional data synchronisation tool that keeps
relational databases in sync across regions.
It supports PostgreSQL, MySQL, and SQLite as both source and target.

ifdef::enterprise[]
Enterprise customers also have access to Oracle and SQL Server connectors.
endif::[]

ifndef::enterprise[]
NOTE: Oracle and SQL Server connectors are available in the Enterprise edition.
Contact sales@example.com for a trial.
endif::[]

=== System Requirements

* 64-bit Linux, macOS, or Windows
* 2 GB RAM minimum (4 GB recommended)
* Network access to source and target databases
* TLS certificates for encrypted connections

=== Installation

. Download the archive for your platform from https://datasync.example.com/releases[the releases page].
. Extract the archive:
+
[source,bash]
----
tar xzf datasync-1.8-linux-amd64.tar.gz
----
. Move the binary to a directory on your `PATH`:
+
[source,bash]
----
sudo mv datasync /usr/local/bin/
----
. Verify the installation:
+
[source,bash]
----
datasync --version
----

== Configuration

{product-name} reads its configuration from `{config-file}` in the current directory
or from a path specified via the `--config` flag.

.Basic configuration
[source,toml]
----
[general]
log_level = "info"
port = {default-port}

[source]
driver = "postgresql"
host = "db-primary.internal"
port = 5432
database = "orders"
username = "sync_reader"

[target]
driver = "mysql"
host = "db-replica.internal"
port = 3306
database = "orders_replica"
username = "sync_writer"
----

TIP: Store credentials in environment variables rather than the config file.
Use `$\{ENV_VAR}` syntax inside `{config-file}` to reference them.

=== Advanced Options

.Conflict resolution strategies
****
When the same row is modified on both sides between sync cycles,
{product-name} must resolve the conflict. Available strategies:

Last-write-wins:: The most recent modification timestamp determines the winner.
Source-priority:: Changes from the source always overwrite the target.
Manual:: Conflicts are logged and must be resolved by an operator.
****

[quote, Werner Vogels]
Everything fails all the time.

This is why {product-name} writes an _audit log_ of every change it applies,
making it possible to replay or revert any synchronisation batch.

== Running a Sync

Start a one-time synchronisation:

[source,bash]
----
datasync sync --config {config-file}
----

For continuous synchronisation use the `watch` subcommand:

[source,bash]
----
datasync watch --interval 30s --config {config-file}
----

WARNING: Running multiple `watch` processes against the same target database
can cause duplicate writes. Use a lock file or orchestration layer to prevent this.

=== Filtering Tables

You can include or exclude tables using glob patterns:

[source,toml]
----
[sync]
include_tables = ["orders_*", "customers"]
exclude_tables = ["orders_archive_*"]
----

=== Monitoring

{product-name} exposes a Prometheus-compatible metrics endpoint on port `{default-port}`:

.Key metrics
[example]
====
`datasync_rows_synced_total`:: Total rows synchronised since startup.
`datasync_sync_duration_seconds`:: Histogram of sync cycle durations.
`datasync_conflicts_total`:: Number of conflicts detected per strategy.
`datasync_errors_total`:: Errors encountered during sync cycles.
====

== Troubleshooting

Connection refused::
  Verify the target database is reachable and the port is correct.
  Check firewall rules and security groups.
+
TIP: Use `datasync ping --config {config-file}` to test connectivity.

Authentication failed::
  Ensure the credentials in `{config-file}` (or the referenced environment variables)
  are correct and that the database user has the required permissions.

Slow synchronisation::
  * Increase `batch_size` in the `[sync]` section.
  * Ensure indexes exist on primary key columns.
  * Check network latency between the {product-name} host and the databases.
  * Consider enabling parallel sync:
+
[source,toml]
----
[sync]
parallel_tables = 4
----

== Security

ifdef::enterprise[]
{product-name} Enterprise supports mutual TLS (mTLS) for all database connections.
Configure client certificates in the `[tls]` section.
endif::[]

All data in transit is encrypted using TLS 1.2 or later.
At-rest encryption depends on the underlying database configuration.

CAUTION: Never commit `{config-file}` files containing plaintext passwords to version control.
